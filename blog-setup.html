Setting Up My Engineering Laptop

Aug 18, 2026 · 4 min read

My laptop is technically a gaming laptop — I bought it thinking about frame rates, not lecture notes. But it's also the only machine I've got, so over the last few weeks it's slowly turned into my actual engineering workstation. Here's what ended up making the cut, and why.

The browser

I use Brave day to day. Built-in ad and tracker blocking means fewer distractions during research, and it's Chromium-based so every extension and dev tool I need just works without compatibility headaches.

The editor

VS Code is doing almost all the heavy lifting. A handful of extensions cover most of what a first-year comp engineering syllabus throws at me:

  • C/C++ and Python extensions for coursework and labs
  • GitLens for actually understanding what a git blame is telling me
  • Error Lens so mistakes show up inline instead of hiding in a separate panel
  • A couple of theme and icon packs, because staring at the same editor for six hours a day should at least look decent

Git and version control

I set up SSH keys instead of typing a password on every push, added a global .gitignore so build files and IDE clutter never make it into a repo, and got in the habit of committing small and often. It felt like unnecessary ceremony for a one-person assignment at first — it stopped feeling that way the first time I needed to undo something.

git config --global user.name "Aavash Khadka"
git config --global user.email "your-email@example.com"
git config --global init.defaultBranch main

The terminal

Since switching to CachyOS, the terminal stopped being a last resort and became the fastest way to do most things — navigating folders, managing packages, running quick scripts. A clean prompt that shows my current git branch and directory at a glance has probably saved me more time than any GUI tool I've installed.

Notes and organization

Lecture notes, lab reports, and half-finished ideas all live in a simple folder-based notes system I keep on the laptop — plain markdown files, organized by subject, searchable from the terminal in seconds. Nothing fancy, but it means nothing gets lost between semesters.

Everything else

  • A PDF reader that doesn't fight me over annotations
  • LibreOffice for reports that need to stay in a standard document format
  • A basic build toolchain (gcc, make) for C labs
  • And yes — Steam, still installed, for the evenings when the laptop gets to just be a gaming laptop again

None of this is a particularly exotic setup. That's kind of the point — most of it is boring, reliable tooling that gets out of the way so I can actually focus on the coursework instead of fighting my own machine.
